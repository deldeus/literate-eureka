# 杰哥工具 5.0 当前版本维护与恢复指南

更新时间：2026-09-04  
当前版本：`v2026.09.04.1`

## 一、恢复工作时先看这里

无论是新的 Codex 任务、对话被压缩，还是换电脑继续维护，都按下面顺序开始：

1. 打开本目录 `杰哥工具5.0`，不要从历史交付包反向修改。
2. 阅读根目录 `AGENTS.md`。
3. 阅读 `docs/杰哥工具5.0-开发入口.md` 的最新变更记录。
4. 需要追溯完整业务规则时，阅读 `docs/杰哥工具4.0-需求归档.md`。
5. 修改前先运行：`node --test tests/regression.test.js`。
6. 修改后再次运行全部测试，并用浏览器实际操作受影响页面。

把这几步交给新的维护任务，即可恢复当前工作状态，不需要重复发送此前的大量截图和聊天记录。

## 二、唯一主版本与权威数据

- 唯一主源码：当前 `杰哥工具5.0` 目录。
- 产品与价格公共数据：`tools/product-data.js`。

- 美利来原始价格表：`docs/美利来价格明细表2026.4.13.xlsx`。
- 鎏金重量、包装、DB、顺心捷达计算核心：`tools/freight-gold-core.js`。
- 宁波合装重量核心：`tools/ningbo-freight-core.js`。
- 顺心捷达费率：`tools/shunxin-rates.js`。

同一业务规则必须通过公共数据或公共核心同步到所有相关页面，不能只改其中一个入口。公共脚本更新后，要同步修改所有引用页面的缓存版本参数。

## 四、仍需人工确认的唯一已知项

`1200×600mm` 鎏金小板目前缺少经过确认的托盘长、宽、高。系统可以核算重量、包装数量和 DB，但顺心捷达体积重与最终运费必须继续提示人工询价。没有新权威数据前不得猜测或静默套用其它托盘尺寸。

## 五、交付与上传

每次完成修改后：

1. 更新首页版本号、上传说明、开发入口和需求归档。
2. 运行全部回归与实际浏览器检查。
3. 生成完整 GitHub 上传包，保留 `index.html`、`README-上传说明.txt`、`AGENTS.md`、`tools/`、`tests/`、`docs/`。
4. 交付目录和 ZIP 必须内容一致，并通过 ZIP 完整性检查。
5. 历史完整包只保留最近 5 个版本。

## 六、长任务防丢失建议

- 已确认的业务规则必须写入需求归档，不只留在聊天中。
- 每轮完成后更新本指南和开发入口，让源码本身成为“记忆”。
- 一个大功能完成并打包后，可以开启新任务继续；新任务只需提供本目录位置并要求先读本指南。
- 不要在一次消息里重复上传全部历史截图；只提供本次新增问题的截图和明确规则。
